# Architecture Note

## Media fixture provenance and licence

The committed media fixtures are development inputs, not application output. The development seed registers them as sources; the application prepares renditions and serves them through `GET /api/media/[assetId]/[rendition]`, which re-authorises every request — playback, poster, caption track, transcript and byte range — so no original ever sits behind a permanent public URL. Preparation uses `file-type` and `mediabunny` only. It is local processing, not production transcoding or scanning, and no surface claims otherwise.

The seed does not serve these files. A reset materialises each seeded rendition's bytes into the store's own `.data/media` custody — copying the video, poster and caption fixtures as they stand and producing the image's display rendition from the EXIF-bearing original with the application's own image pipeline — so the bytes a request can reach are the ones the records name. `src/proxy.ts` additionally denies that directory on the decoded request path, so every spelling of it — the plain one, the percent-encoded separator, a `%6D` or `%66` first letter, the double-encoded form, a mixed-case or backslash-separated one and a dot-segment form — answers the same 404 a missing file does, even though the files stay committed as inputs to the seed and to the upload path. Custody plus the re-authorising route therefore remain the only way to a rendition's bytes, and the guard sits at the request level because the framework decodes the path before it resolves a `public/` file, which is what a rule keyed on the literal path missed.

## UI SDK behaviour adapter and design-system gap register

`apps/dashboard/src/lib/ui-sdk.ts` is the only file that imports `@ui-sdk/*`. It exposes four own-named behaviours — `useDismissableLayer`, `useRovingFocus`, `useTypeahead` and `useModalFocusContainment` — so components call the adapter and never the SDK itself. Base UI is not imported there: it stays the primitive substrate inside `src/components/ui` and the documented fallback for a component the SDK cannot serve, and the adapter is what keeps the SDK-first choice real.

**Inspected export list (`@ui-sdk/core` 0.1.0-beta.13, `@ui-sdk/react` 0.1.0-beta.13).** The core package publishes only its root entry, per-component entries, `renderer` and `testing`; its `foundation/*` modules are internal and unreachable. From the installed declarations, the root entry exports `bindLayer` (with `LayerDismissReason`), `keepFocus`, `createFocusRecovery`, `createRovingFocus` (with `RovingFocus`, `RovingFocusItem`, `RovingFocusOptions`, `RovingOrientation`), `createClaim`, `createTypeahead`, `isTypeaheadKey`, `labelOf`, `isComposing`, `createListbox`, `createPopup` plus the popup presets on their component entries, `bindPersistentLayer` and the `Store` type. The React package exports the hooks `usePrimitive`, `usePart`, `useNearest`, `useHandle`, `useAround`, `usePreference`, `useShortcut`, `useShortcutHint`, `useAsyncOptions`, `useFieldControl`, `useJoinField`, `usePlacedContent`, `useSegment` and `useToolbarScope` — none of them is one of the four behaviours; its `./primitive` subpath also exports the React-level helpers `mergeProps` and `renderElement`. The adapter builds the item props it hands back on `mergeProps` rather than hand-writing them, because core is framework-agnostic: joining a behaviour's props to the caller's own handlers, `ref`, `className` and `style` is the React binding's job, and doing it here would copy dependency source.

### Gap: modal focus containment

- **Interaction.** The shared review step and the media picker are modal dialogs composed outside `src/components/ui`: initial focus must land inside, Tab and Shift+Tab must wrap within it, Escape must request a close, and focus must return to the invoking control.
- **Package and version consulted.** `@ui-sdk/core` 0.1.0-beta.13 and `@ui-sdk/react` 0.1.0-beta.13.
- **What fails without a substitution.** The SDK's dialog preset contains focus and makes the rest of the page inert, but it is reachable only through a whole popup primitive (`definePrimitive` + `createPopup` + rendered parts), which a behaviour-only adapter cannot host without becoming a component. `bindLayer` alone dismisses on Escape and blocks presses outside, yet leaves the Tab cycle free, and the helpers it uses internally (`inertOutside`, the tabbable scan) are not exported from any public entry. A dialog built on that alone lets Tab walk out of it, breaking focus order for keyboard users (WCAG 2.2 SC 2.4.3) and leaving the dialog's own controls hard to reach on repeat visits.
- **Substitution.** The adapter supplies exactly that missing step, and nothing else, in `useModalFocusContainment`: focus lands on the caller's `initialFocusRef` or the first tab stop inside the dialog, a document-level Tab handler wraps forward and backward within the dialog, `bindLayer({ modal: true })` keeps outside presses from reaching the page and reports Escape, and `keepFocus` restores the invoking control on close. The handler and the layer are released in one cleanup, so the page is fully reachable the moment the dialog closes (SC 2.1.2). The dialog's `role`, accessible name and `aria-modal` stay with its own markup, as the hook's documentation states.

No gate checks format — `bun run format` writes in place and no task runs `oxfmt --check` — so the width is a stated choice about the tree's canonical form rather than an enforced one.

## Measured workload and performance

The published workload is the one `bun run seed:workload` (`scripts/generate-workload.ts`) writes for the seeded `established-worker` session: **10,000 partners and 100,000 gift rows**, generated deterministically from a fixed seed into `<sessionId>.workload.json`. That document is 67,229,868 bytes and holds 99,802 gifts plus the 198 allocation rows of 99 split gifts. Every number below is an observation on the machine this section names, taken with the method attached, with no change to the generator, the seed or the query to move it; none of them is a capacity promise (AAP 0.8.9 A16).

**How the measurement is taken.** From `apps/dashboard`, `WORKLOAD_MEASUREMENT=1 bunx vitest run tests/integration/workload-timing.test.ts` runs the timing spec; without that variable the file is skipped, so the ordinary gate stays fast. The tree holds no Gifts page and no `/api/support` route yet, so what is timed is the server half those surfaces will call — the service read for the named session plus the `JSON.stringify` of the envelope a page transport receives — and the first meaningful render the target's phrasing includes has no surface here to be timed in.

- **Filtered Gifts page.** `reads.support.readGifts({ period: { kind: "explicit", from: "2025-11-01", to: "2026-10-31" }, currency: "USD", page: { index: 0, size: 50 }, timeZone: "UTC" }, { sessionId: "established-worker" })` — 3 warm-up calls discarded, then 30 timed samples; p95 is the nearest-rank value, the samples sorted ascending and taken at index `ceil(0.95 × 30) − 1`. The whole result behind that page is 10,878 USD rows, and the serialised envelope is 1,314,436 bytes; serialising it costs 3–9 ms of the sample, so the figure is dominated by the read itself.
- **Full CSV export.** `reads.export.readExport({ period: { kind: "explicit", from: "2022-11-20", to: "2026-11-21" }, timeZone: "UTC" }, { sessionId: "established-worker" })` — no currency filter and no page, so the whole generated query is written — timed once.

**The machine.** An Intel Xeon Platinum 8581C at 2.10 GHz, 3,145,377,214,464 bytes of RAM (2.86 TiB), Linux 6.12.105+, Node v26.13.1 (the spec runs in vitest's Node worker, `bunx` only launches it). `os.cpus()` reports the host's 112 processors while this container is scheduled on **12** of them (`nproc` reports 12), and the host is shared with the other work running against it, so every run records the load average it began at.

| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------ | ------- |
| Filtered Gifts read — 3 warm-ups discarded, 30 samples         | min 75.9 ms, median 80.8 ms, p95 **87.2 ms**, max 89.8 ms (load average 9.90 / 10.59 / 12.64) | p95 < 500 ms | **Met** |
| Full CSV export — timed once                                   | **8,381.7 ms** for **99,911 rows** (99,928 CSV lines, header and metadata lines included)     | under 30 s   | **Met** |

**Why the read costs what it costs, and what changed.** The read is a whole-dataset operation: it reads the session's documents, validates the document set, projects 100,000 gift rows into report rows and aggregates the report. Three caches remove the parts that need not happen twice, and each is invalidated by the bytes rather than by a timer or a caller:

- `modules/store/repository.ts` holds the parsed document set until the modification time or size of any of the session's four files changes, and drops the entry whenever this process writes or re-seeds, so a mutation, `bun run reset` or the workload generator is always seen by the next read;
- `reads/support.ts` holds the validated workload document against the document object the store hands back, so the 100,000 rows are validated once per document version rather than once per read;
- `reads/support.ts` holds the support projection against that same object, keyed by the support record's revision and the read's as-of instant, so a goal save (which bumps the revision) or a development clock change (which moves the as-of instant) builds a fresh projection.

Before those caches the same measurement, run the same way on the same workload, reported p95 **1,726.7 ms** (min 1,316.9 ms), 2,052.9 ms, 2,862.9 ms and 4,391.7 ms: every read re-parsed the 67,229,868-byte document — reading and `JSON.parse`-ing it alone costs 179.7–224.1 ms — and re-validated all 100,000 rows before rebuilding the projection, so a page paid a whole-dataset parse per request. The export told the same story: 9,756.4 ms, 10,108.3 ms, 10,811.1 ms, 11,532.9 ms and 12,446.6 ms before the caches, **8,381.7 ms** after.

**The export target is met.** The whole query was written in 8,381.7 ms, inside 30 s. It states `rowCount` 99,911 — equal to the report's whole-result count and to the printed model's row total, both asserted — which is below the document's 100,000 rows because the grain is one authorised allocation: a gift with no allocation counts once, and a split gift contributes only the allocation this ministry may see.

**Tracked line count.** `bun run lines` runs the request's command verbatim, `git ls-files | grep -v -e '^bun.lock$' | xargs wc -l`, and it prints `TOTAL 98537` against `LIMIT 100000` — `STATUS PASS`, exit 0 — so the delivered tree stands at **98,537 tracked lines**, 6,192 of them the `wc` line counts of the six binary media fixtures the request excludes (92,345 without them). The figure covers tracked files only, because `git ls-files` lists nothing else, and the measurement command is unchanged from the request's own pipeline.

**`Virtual` is not installed.** `@tanstack/react-virtual` stays out because no rendered-row measurement crossed a threshold: the table paginates at 50 rows, capped at 200, over pages the service processes, so no surface renders a window large enough to need a virtualiser. `Virtual` is added only after a documented measurement that says so — a rendered-row timing on a real page, recorded here in the same shape as the two numbers above.

## Release transport: two refused parameters and one write

`GET /api/variants` states two search parameters, `view` and `variantId`, and refuses `audience` and `locale` by name instead of accepting either. `readRelease` accepts `{ variantId, releaseId?, session? }` and `readSharePresentation` accepts `{ variantId, session? }`: an edition's audience and locale are properties of the variant that `variantId` identifies, and both reads state that edition's own audience and locale in the envelope. There is therefore no filter for either parameter to reach, and the route does not invent a second read to give them one, so a request that states one is answered `invalid` before the query grammar runs, with its message keyed to that parameter's own name — a parameter stated twice included. A caller is thus told no filter was applied, rather than reading one edition believing it had chosen another.

`POST /api/variants` creates one Update edition through `mutations.updates.createVariant`: one family-permitted audience in one exact content locale, with no draft, candidate or release yet. The body is strict at both levels — `operationId`, `scope` and `expectedRevision` with a payload of `documentId`, `audience` and `locale` — and the family is the route's decision, pinned to `update`, so a request cannot create a Page edition through this path, nor carry a draft, a candidate, a notification intent or a membership through it. A variant's draft, review, release, notification and withdrawal writes keep the handlers of their own paths.

## Delivered structure: the transport-support and boundary files

The plan's tree enumerates the application's planned structure; the delivered tree adds twelve files that are the transport-support and boundary layer of the modules that tree does enumerate. Each is the single owner of the concern it serves, none restates a concern the plan already gives one owner, and none exists to serve an excluded integration.
