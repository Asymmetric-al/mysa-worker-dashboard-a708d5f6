# Architecture Note

## Media fixture provenance and licence

The committed media fixtures are development inputs, not application output. The development seed registers them as sources; the application prepares renditions and serves them through `GET /api/media/[assetId]/[rendition]`, which re-authorises every request — playback, poster, caption track, transcript and byte range — so no original ever sits behind a permanent public URL. Preparation uses `file-type` and `mediabunny` only. It is local processing, not production transcoding or scanning, and no surface claims otherwise.

### `apps/dashboard/public/fixtures/media/sample-h264.mp4`

| Property            | Value                                                                                                                                                                                        |

| Source              | `https://mdn.github.io/shared-assets/videos/flower.mp4` (MDN shared assets; the same file is published in the MDN `interactive-examples` repository under `live-examples/media/cc0-videos/`) |

| SHA-256             | `0cd83d944a6ca7822b4a8306cecc60a36e859b041f6702c6a1ad9ead78924451`                                                                                                                           |
| Container           | MP4 (ISO base media file format, `ftyp` brand `mp42`, compatible brands `mp42 mp41 isom avc1`)                                                                                               |
| Video               | H.264 (`avc`), coded and displayed 960 × 540, rotation 0, 29.97 fps                                                                                                                          |
| Audio               | AAC, 48 kHz, 2 channels                                                                                                                                                                      |
| Duration            | 5.056 s as reported by the media inspector; 5.055 s container duration                                                                                                                       |
| Profile             | Within the admitted video profile: MP4 with H.264 video and AAC audio, at most 100 MiB, at most 180 s, at most 1920 × 1080 after rotation is applied                                         |
| Runtime requirement | None beyond the browser's own decoder. Playback needs no encoder, no external binary and no server-side transcode.                                                                           |

**How the values above were measured.** Content typing with `file-type` 22.3.0 returns `video/mp4` from the magic bytes, so the type never rests on the `.mp4` extension. Container, duration, codecs, dimensions and rotation come from `mediabunny` 1.66.2. Playback was verified in a real browser: the clip loads its metadata, plays in real time, seeks to an exact position mid-playback and from a paused load, and runs to its end with no media error, served with `206 Partial Content` so seeking follows the same byte-range path the application's media route provides.

**Tags in the committed original, and why they matter.** The source carries the source-encoder tags `handler_name: "L-SMASH Video Handler"`, `encoder: "AVC Coding"`, `language: "und"` and a `creation_time` of 2018-03-07. The fixture keeps the source bytes unmodified; the video pipeline produces a copy-remux with no descriptive tags and verifies the served rendition before admitting it, so these source tags never reach a reader. As assumption A7 records, container creation and modification timestamps may survive a copy-remux, and the pipeline rejects a rendition that still reports a descriptive tag rather than serving it.

## UI SDK behaviour adapter and design-system gap register

`apps/dashboard/src/lib/ui-sdk.ts` is the only file that imports `@ui-sdk/*`. It exposes four own-named behaviours — `useDismissableLayer`, `useRovingFocus`, `useTypeahead` and `useModalFocusContainment` — so components call the adapter and never the SDK itself. Base UI is not imported there: it stays the primitive substrate inside `src/components/ui` and the documented fallback for a component the SDK cannot serve, and the adapter is what keeps the SDK-first choice real.

**Inspected export list (`@ui-sdk/core` 0.1.0-beta.13, `@ui-sdk/react` 0.1.0-beta.13).** The core package publishes only its root entry, per-component entries, `renderer` and `testing`; its `foundation/*` modules are internal and unreachable. From the installed declarations, the root entry exports `bindLayer` (with `LayerDismissReason`), `keepFocus`, `createFocusRecovery`, `createRovingFocus` (with `RovingFocus`, `RovingFocusItem`, `RovingFocusOptions`, `RovingOrientation`), `createClaim`, `createTypeahead`, `isTypeaheadKey`, `labelOf`, `isComposing`, `createListbox`, `createPopup` plus the popup presets on their component entries, `bindPersistentLayer` and the `Store` type. The React package exports the hooks `usePrimitive`, `usePart`, `useNearest`, `useHandle`, `useAround`, `usePreference`, `useShortcut`, `useShortcutHint`, `useAsyncOptions`, `useFieldControl`, `useJoinField`, `usePlacedContent`, `useSegment` and `useToolbarScope` — none of them is one of the four behaviours.

| Behaviour | Classification | What the SDK supplies, and what the adapter adds |
| --- | --- | --- |
| `useDismissableLayer` | Supplied | `bindLayer` handles Escape, a press outside the layer and outside its trigger, the window losing focus and the modal press-block; `keepFocus` returns focus to the trigger. The adapter only carries the newest callbacks so a parent render never rebinds the layer mid-interaction. |
| `useRovingFocus` | Supplied | `createRovingFocus` decides the single tab stop (with `disabled`, `preferred`, claims and remembering the item focused last), moves on Up/Down/Left/Right/Home/End in either text direction, wraps when asked, and never traps focus. It expects a primitive's context, so the adapter hosts one small store carrying the tab stop and the group's options. |
| `useTypeahead` | Supplied | `createTypeahead` accumulates the buffer, continues it on Space, steps through items sharing a prefix and clears it after the idle interval; `isTypeaheadKey` and `isComposing` gate the keys. The adapter keeps a buffer that stops matching from swallowing typing, and leaves a text entry's own typing alone. |
| `useModalFocusContainment` | Partial | See the gap entry below. |

### Gap: modal focus containment

- **Interaction.** The shared review step and the media picker are modal dialogs composed outside `src/components/ui`: initial focus must land inside, Tab and Shift+Tab must wrap within it, Escape must request a close, and focus must return to the invoking control.
- **Package and version consulted.** `@ui-sdk/core` 0.1.0-beta.13 and `@ui-sdk/react` 0.1.0-beta.13.
- **What fails without a substitution.** The SDK's dialog preset contains focus and makes the rest of the page inert, but it is reachable only through a whole popup primitive (`definePrimitive` + `createPopup` + rendered parts), which a behaviour-only adapter cannot host without becoming a component. `bindLayer` alone dismisses on Escape and blocks presses outside, yet leaves the Tab cycle free, and the helpers it uses internally (`inertOutside`, the tabbable scan) are not exported from any public entry. A dialog built on that alone lets Tab walk out of it, breaking focus order for keyboard users (WCAG 2.2 SC 2.4.3) and leaving the dialog's own controls hard to reach on repeat visits.
- **Substitution.** The adapter supplies exactly that missing step, and nothing else, in `useModalFocusContainment`: focus lands on the caller's `initialFocusRef` or the first tab stop inside the dialog, a document-level Tab handler wraps forward and backward within the dialog, `bindLayer({ modal: true })` keeps outside presses from reaching the page and reports Escape, and `keepFocus` restores the invoking control on close. The handler and the layer are released in one cleanup, so the page is fully reachable the moment the dialog closes (SC 2.1.2). The dialog's `role`, accessible name and `aria-modal` stay with its own markup, as the hook's documentation states.

## Lint gap register

`.oxlintrc.json` at the repository root carries the five layering and correctness invariants at Oxlint 1.94.0. Version 1.94.0 has no `no-restricted-syntax` rule, so two invariants have no rule that expresses them directly. Each uses the closest supported rule, and the review check beside it closes the remainder; no second linter, plugin package or wrapper is installed for them.

| Invariant                                                                                                 | Supported rule in use                                                                                                                                                                                    | What it does not catch, and the review check that replaces it                                                                                                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No raw colour literals in `src/components` and `src/features`                                             | `react/style-prop-object` rejects a string-valued `style` prop; `no-restricted-imports` rejects `tailwindcss/colors` and `tailwindcss/defaultTheme`, the only palette source a component could reach for | A hex, `rgb()`, `hsl()` or `oklch()` value inside a style object or a class string. Review: `grep -rnE '#[0-9a-fA-F]{3,8}\|rgba?\(\|hsla?\(\|oklch\(' apps/dashboard/src/components apps/dashboard/src/features` returns nothing; colour values live only in `src/styles/globals.css`. |
| No floating-point money arithmetic in `src/modules/money`, `src/modules/support` and `src/modules/export` | `no-restricted-properties` forbids `Math.round`, `toFixed` and `Number.parseFloat` in those folders; `no-loss-of-precision` stays at error everywhere                                                    | Binary `+`, `-`, `*` and `/` on an amount, and the bare `parseFloat` global. Review: every amount in those folders is read and combined through `modules/money`, and the `money` domain tests cover a three-decimal and a zero-decimal currency.                                       |
| No circular dependencies                                                                                  | `import/no-cycle` at error, which resolves relative specifiers                                                                                                                                           | A cycle closed through `@/…` alias imports, which the rule's resolver does not follow. Review: a new pair of modules that import each other under the alias is caught by reading the import lines of the new module, and `tsc --noEmit` stays the compile-time gate.                   |
| Feature-to-feature isolation                                                                              | One override per feature folder, forbidding `@/features/**` with that folder's own subtree negated                                                                                                       | A relative specifier such as `../updates/copy`, which carries no `features` segment for the matcher to see. Review: cross-folder imports use the `@/features/…` alias, which the rule covers.                                                                                          |
| Store access outside the service                                                                          | `no-restricted-imports` with a regex covering both `@/modules/store/…` and a relative path into `modules/store`                                                                                          | Nothing outstanding.                                                                                                                                                                                                                                                                   |

Three configuration decisions belong beside these. `react/set-state-in-effect` is off inside `src/components/ui` only: that folder is shadcn-generated source the CLI rewrites rather than hand-edits, the rule targets React Compiler optimisation rather than behaviour, and it stays at error in every hand-written folder. And the application's `lint` script must keep invoking `oxlint --config ../../.oxlintrc.json`, because every scope glob in the one root configuration is written with a `**/` prefix so the same file matches when lint runs from the repository root and from `apps/dashboard`.

A third decision is scoped to `src/components/scroll-region.tsx`: `jsx-a11y/no-noninteractive-tabindex` admits a focusable `section` in that one file. WCAG 2.2 2.1.1 Keyboard requires the application's single horizontally scrollable region to take focus, so keyboard users can scroll it with the arrow keys, and the rule otherwise refuses `tabIndex` on the `section` that carries the region landmark. The rule stays at error in every other file.
